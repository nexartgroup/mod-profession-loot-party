# mod-profession-loot-party

AzerothCore WotLK 3.3.5a module that gives eligible group/raid members independent profession loot rolls when another member successfully gathers a resource.

## Supported professions

* Mining
* Herbalism
* Skinning

## Supported gathering implementations

* Normal AzerothCore Mining
* Normal AzerothCore Herbalism
* Normal AzerothCore Skinning
* `mod-auto-gather` Mining
* `mod-auto-gather` Herbalism
* `mod-auto-gather` Skinning

## How it works

The player who actually gathers the resource keeps the normal AzerothCore loot.

Other nearby group/raid members who have the same profession receive independent rolls against the same profession loot table.

The rolls are generated independently. The module does not copy the original player's loot result.

For Mining and Herbalism, the module uses the GameObject's existing loot template.

For Skinning, the module uses the creature's `SkinLootId` and `LootTemplates_Skinning`.

## Profession multipliers

Each profession has its own configurable multiplier:

```ini
ProfessionLootParty.MiningMultiplier = 1
ProfessionLootParty.HerbalismMultiplier = 1
ProfessionLootParty.SkinningMultiplier = 1
```

The multiplier represents the **total number of loot rolls each eligible profession user receives**.

### Multiplier = 1

Suppose Alice, Bob and Carol all have Mining.

Alice mines a node:

```text
Alice -> normal AzerothCore Mining loot
Bob   -> 1 independent Mining roll
Carol -> 1 independent Mining roll
```

This is the normal module behavior.

### Multiplier = 3

With:

```ini
ProfessionLootParty.MiningMultiplier = 3
```

Alice mines a node:

```text
Alice:
    normal AzerothCore Mining loot
    + independent Mining roll #2
    + independent Mining roll #3

Bob:
    independent Mining roll #1
    independent Mining roll #2
    independent Mining roll #3

Carol:
    independent Mining roll #1
    independent Mining roll #2
    independent Mining roll #3
```

Therefore everybody ends up with three total Mining loot rolls.

The gatherer's first roll is the normal AzerothCore roll. The additional gatherer rolls are generated by the module.

Other group members do not have a normal gathering roll, so they receive the complete configured number of independent rolls.

## Example configuration

For:

* Mining = 1x
* Herbalism = 2x
* Skinning = 5x

use:

```ini
ProfessionLootParty.Enable = 1

ProfessionLootParty.Mining = 1
ProfessionLootParty.MiningMultiplier = 1

ProfessionLootParty.Herbalism = 1
ProfessionLootParty.HerbalismMultiplier = 2

ProfessionLootParty.Skinning = 1
ProfessionLootParty.SkinningMultiplier = 5

ProfessionLootParty.Distance = 100
ProfessionLootParty.Raid = 1
ProfessionLootParty.RequireSkill = 1
ProfessionLootParty.Debug = 0
```

The result is:

| Profession   | Gatherer                          | Other eligible group members |
| ------------ | --------------------------------- | ---------------------------- |
| Mining 1x    | Normal loot                       | 1 independent roll           |
| Herbalism 2x | Normal loot + 1 independent roll  | 2 independent rolls          |
| Skinning 5x  | Normal loot + 4 independent rolls | 5 independent rolls          |

## Multiplier = 0

A multiplier of `0` disables module-generated rolls for that profession.

For example:

```ini
ProfessionLootParty.MiningMultiplier = 0
```

means the module does not generate additional Mining loot.

The original gatherer's normal AzerothCore Mining operation is not removed or modified.

For a completely disabled profession, the corresponding enable option can also be set to `0`.

## Maximum multiplier

The module clamps each multiplier to:

```text
100
```

This prevents an accidental configuration such as:

```ini
ProfessionLootParty.MiningMultiplier = 1000000
```

from generating an extreme number of loot-generation operations.

## Eligibility

A receiving group/raid member must:

* Be in the same group/raid.
* Be alive.
* Be in the world.
* Be within the configured distance.
* Be in the same phase.
* Have the corresponding profession.
* Have a non-zero profession skill when `RequireSkill = 1`.

Raid members are included when:

```ini
ProfessionLootParty.Raid = 1
```

## Normal Mining and Herbalism

Normal AzerothCore Mining/Herbalism gathering is detected through the GameObject loot-state callback and the subsequent gathering skill update.

The module verifies the GameObject through its skill-up list before distributing additional loot.

The original gathering path is left intact.

## mod-auto-gather Mining and Herbalism

`mod-auto-gather` does not necessarily follow the same GameObject activation path as normal AzerothCore gathering.

The module therefore has a fallback that identifies the GameObject processed by AutoGather using:

* GameObject state
* Spawn state
* Map
* Phase
* Distance
* Skill-up list
* Lock data
* Required profession

Once the successful gathering operation is identified, the same multiplier/distribution logic is used.

## Skinning

Skinning is handled separately because it does not use the same GameObject loot-state callback as Mining and Herbalism.

The module supports both:

### Normal AzerothCore Skinning

The successful skinning operation results in a `LOOT_SKINNING` state and a `SKILL_SKINNING` gathering-skill update.

### mod-auto-gather Skinning

The module also supports the behavior used by `mod-auto-gather`'s `AutoSkinCreature()`.

The corpse is identified using:

* Dead creature
* Same map
* Same phase
* Distance
* `LOOT_SKINNING`
* Valid `SkinLootId`
* Required loot skill = Skinning
* `UNIT_FLAG_SKINNABLE` removed
* Creature tapped by the skinner

The module then generates independent Skinning rolls using the creature's `SkinLootId`.

## Independent rolls

Each additional roll calls the corresponding loot system again.

Mining/Herbalism:

```cpp
player->AutoStoreLoot(
    lootId,
    LootTemplates_Gameobject,
    true);
```

Skinning:

```cpp
player->AutoStoreLoot(
    lootId,
    LootTemplates_Skinning,
    true);
```

Therefore each roll is independent.

For example, with a 3x Mining multiplier, three rolls could independently produce different quantities and different chance-based items.

## Gatherer versus other group members

The module intentionally treats the original gatherer differently.

The original gatherer has already received the normal AzerothCore/AutoGather loot.

Therefore:

```text
Total multiplier = N

Original gatherer:
    normal core roll
    + (N - 1) module rolls

Other eligible member:
    N module rolls
```

This ensures every eligible profession user receives the same total number of rolls without replacing the normal gathering implementation.

## Installation

Place the module in:

```text
azerothcore/modules/mod-profession-loot-party/
```

A typical module layout is:

```text
mod-profession-loot-party/
├── conf/
│   └── mod-profession-loot-party.conf.dist
├── src/
│   ├── ProfessionLootParty.cpp
│   └── ProfessionLootParty.h
├── CMakeLists.txt
└── README.md
```

Copy the configuration file to the server configuration directory if your AzerothCore setup does not automatically install `.conf.dist` files.

For example:

```text
etc/modules/mod-profession-loot-party.conf
```

Then configure the desired profession multipliers.

## Important

This module does not modify AzerothCore's normal gathering loot.

It adds independent rolls after a successful gathering operation.

Consequently, setting:

```ini
ProfessionLootParty.MiningMultiplier = 1
```

does not make the gatherer's normal Mining loot come from the module. The normal AzerothCore gathering operation remains responsible for the original loot.

## Example

Three players:

```text
Alice  - Mining
Bob    - Mining
Carol  - Mining
```

Configuration:

```ini
ProfessionLootParty.MiningMultiplier = 3
```

Alice mines:

```text
Alice:
    Core Mining roll
    Module Mining roll #2
    Module Mining roll #3

Bob:
    Module Mining roll #1
    Module Mining roll #2
    Module Mining roll #3

Carol:
    Module Mining roll #1
    Module Mining roll #2
    Module Mining roll #3
```

All three players therefore receive three total independent Mining outcomes.

The same model applies independently to Herbalism and Skinning.

## Compatibility

Designed for:

* AzerothCore
* WotLK 3.3.5a
* `mod-auto-gather`

The module does not require `mod-auto-gather` to be installed for normal gathering functionality.
